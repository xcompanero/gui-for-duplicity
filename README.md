# GUI For Duplicity

A desktop GUI front end for the [Duplicity](https://duplicity.gitlab.io/)
backup program, written in Rust for Kubuntu / KDE Plasma.

Created because Déjà Dup abandoned the duplicity backend in favour of Restic —
taking with it the verbosity, visible progress, easy verification and usable
restores that made duplicity feel trustworthy. This project puts the duplicity
engine back behind a proper desktop interface.

**No Python is involved in the GUI itself** — duplicity is driven purely
through its command line, spawned and monitored by a Rust engine.

## Features

- **Profiles** — declarative TOML backup jobs: sources, target URL (any
  duplicity backend: `file://`, `sftp://`, `ftp://`, S3, B2, …), include and
  exclude globs, GPG options, retention, schedule.
- **Verbose live logs** — every duplicity invocation streams its output into
  the GUI in real time. You can always see what is happening.
- **Snapshot browser** — browse the complete file tree of any backup set,
  including **historical states**: every backup set in every chain has a
  "browse as of" view.
- **Safe restores** — select any file or folder, restore to a chosen
  destination (or its original location), with duplicity's
  never-overwrite guarantee surfaced honestly. Restores of a single 18 kB
  file and whole folders both work.
- **Verification** — a first-class *verify* action compares the backup's
  data against the source and reports a clear verdict with a difference list.
- **Secrets handled properly** — GPG passphrases are stored in the
  desktop's secret service (KWallet / ksecretd on KDE) and passed to
  duplicity via the environment, never on a command line and never in
  plaintext config.
- **Scheduled backups** — per-profile systemd user timers (`Persistent=true`,
  so missed runs catch up after downtime), managed from the GUI or CLI and
  visible in normal systemd tooling.
- **Retention** — automatic `remove-older-than` and `cleanup` housekeeping
  after successful backups, with a dry-run preview.
- **Notifications** — desktop alerts for failed backups, and for long
  successful ones.
- **Restore-only profiles** — a frozen archive (e.g. a pre-reinstall machine
  history) can be marked read-only: browsing and restoring are welcome,
  backups are impossible.

## The engine architecture

One Rust library crate (`engine`) contains *everything* the project knows
about duplicity: command building, process running, output parsing, profile
handling, caching. The GUI (Tauri v2) and the CLI (`engine-cli`) are thin
clients of it. This means:

- the CLI alone can back up, verify, restore, browse and manage schedules —
  fully headless, as systemd services do;
- the listing cache turns duplicity's expensive re-parse of signature
  archives (tens of minutes on large targets) into an instant lookup,
  invalidated automatically when a new backup lands.

## Requirements

- Linux with systemd user session (developed on Kubuntu 26.04)
- duplicity 3.x on PATH
- Rust stable toolchain (to build)
- Tauri v2 system dependencies on Debian/Ubuntu:
  `libwebkit2gtk-4.1-dev libgtk-3-dev libayatana-appindicator3-dev
  librsvg2-dev libssl-dev libdbus-1-dev`

## Building and installing

```bash
cargo build --release
./scripts/install.sh        # installs to ~/.local/bin + menu entry
```

`install.sh` places `gui-for-duplicity` and `engine-cli` in `~/.local/bin`,
installs a desktop entry and icon, and keeps them side-by-side so systemd
units generated by the tool find the right binary.

**Debian/Ubuntu package** (recommended for installing on other machines):

```bash
cargo build --release
./scripts/build-deb.sh      # produces dist/gui-for-duplicity_<version>_amd64.deb
sudo apt install ./dist/gui-for-duplicity_<version>_amd64.deb
```

The package declares its runtime dependencies (duplicity, webkit2gtk,
libnotify) so `apt` resolves them automatically. Binaries install to
`/usr/bin`; profiles live in `~/.config/gui-for-duplicity/` per user.

Uninstall with `./scripts/uninstall.sh` (or `sudo apt remove
gui-for-duplicity` for the package). Profiles in
`~/.config/gui-for-duplicity/` and any backup data are untouched either way.

## Usage

- **GUI**: launch *GUI For Duplicity* from the menu or run
  `~/.local/bin/gui-for-duplicity`.
- **Headless**:

  ```bash
  engine-cli backup <profile> [--force-new-chain]   # what systemd runs
  engine-cli status <target-url>                    # parsed collection-status
  engine-cli files <target-url> [--time <t>]        # snapshot file listing
  engine-cli verify <target> <source>               # data verification
  engine-cli restore <target> <dest-dir> --file <path> [--time <t>]
  engine-cli schedule <profile> <on-calendar|off>
  engine-cli delete <profile>                       # removes timer units too
  ```

Secrets may also be supplied to the CLI via the environment
(`ENGINE_PASSPHRASE`, `ENGINE_BACKEND_PASSWORD`) or the desktop secret
service, which it reads automatically.

## Known limitations

- Historical ("as of") browsing parses duplicity's signatures on first use:
  minutes on small targets, potentially an hour on large remote ones. Each
  date is cached permanently afterwards.
- The Tauri window is the only UI; there is no tray icon yet.
- Developed and tested against duplicity 3.0.x on Kubuntu/KDE Plasma, with
  backup targets exercised on a Synology NAS (sftp and ftp) and a plain
  Ubuntu server (sftp). The GUI uses desktop-agnostic freedesktop
  interfaces (Secret Service, systemd user units, freedesktop
  notifications), but desktop environments beyond KDE Plasma are untested —
  testers for GNOME, Cinnamon, MATE, and other distros are welcome.
